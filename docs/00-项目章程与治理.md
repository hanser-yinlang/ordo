## 1. 项目目标

**一句话目标**:在 12 周内交付一套可上架级别的多端待办应用,业务核心只写一遍(Android/Windows 共享 KMP 核心),鸿蒙端按同一契约独立实现。

### 1.1 业务目标(可验证)

| 编号 | 目标 | 验收方式 |
|---|---|---|
| G1 | 四端均可完成"收集 → 排期 → 执行 → 回顾"完整闭环 | 每端跑通 8 条核心用户旅程(见 PRD §4) |
| G2 | 多设备数据一致:一台设备打勾,另一台 3 秒内可见 | 集成测试:两端并发写 + 冲突用例 |
| G3 | 中文自然语言录入可用(日期/时间/标签) | 契约 §5 全部写法逐条通过单元测试 |
| G4 | 共享核心单元测试覆盖率 ≥ 80%(核心规则 100%) | 覆盖率报告 + 契约条款逐条对照 |
| G5 | 自研品牌视觉与命名,零第三方商标风险 | 合规检查清单(见 07 号文档) |

### 1.2 非目标(本期明确不做)

- 团队协作/共享清单(参考产品也不支持)
- Web 端与浏览器访问(仅保留原型作为设计参考)
- 端到端加密与自建证书体系(采用 HTTPS + 服务端 AES 落盘策略)
- Vision Pro / Watch 端(列入二期)

## 4. 治理机制

### 4.1 需求与变更

1. 任何字段/接口/行为变更 → **先改 `docs/03` 契约**并升版本号,再改代码。
2. 契约变更需评估四端影响面,在文档"变更记录"表中登记。
3. UI 变更走 `docs/04`,令牌值变更须四端同步。

### 4.2 质量门(每个工作包交付前必须自证)

| 门 | 要求 |
|---|---|
| 编译门 | 能编译的端必须真实编译通过;不能编译的端(本机无 SDK/无 macOS)必须注明并给出静态检查结论 |
| 测试门 | 纯逻辑必须带单元测试;核心规则覆盖率 100% |
| 契约门 | 字段名、错误码、路由、清单规则逐条对照文档 |
| 范围门 | 只改自己工作包目录,禁止跨端改动(集成由架构师统一做) |

### 4.3 汇报格式(统一)

每次交付必须包含:①文件树与行数 ②契约对照表 ③自检命令与**真实输出** ④未完成/风险 ⑤下一步 TODO。

### 4.4 工具与协作

- 版本管理:Git 主干 + 短生命周期特性分支(规范见 08 号文档)
- 构建:共享核心与桌面端用 Gradle;后端用 pnpm;Android 用 Gradle + AGP;鸿蒙用 DevEco
- 缺陷管理:统一登记在 `docs/05` 的缺陷表;阻断级缺陷不得进入下一里程碑

## 5. 资源与环境约束(已知事实)

| 约束 | 影响 | 应对 |
|---|---|---|
| 开发机为 Windows,无 Android SDK / DevEco | Android、鸿蒙无法在本机编译 | 本机完成共享核心与桌面端真实构建;其余端做静态检查 + 契约核对,并给出目标环境构建步骤 |
| 无 PostgreSQL 实例、无 Docker | 后端无法连真实库 | 仓储抽象 + 内存实现跑测试;提供 `migrations/001_init.sql` 与部署文档 |
| 无真实日历/推送服务 | 系统集成只能做到接口层 | 以适配器接口 + 本地通知实现,预留系统日历接入点 |
