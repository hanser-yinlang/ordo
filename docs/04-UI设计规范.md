## 5. 关键动效(统一时序,四端一致)

**完成一条待办**(从触摸/点击到从列表消失)

| 时间 | 动作 |
|---|---|
| 0ms | 按压反馈:复选框 scale → 0.92(90ms) |
| 80ms | 圆圈填充 `accent.primary`(scale 0.92 → 1.06 → 1,spring) |
| 160ms | 白色对勾 stroke-dashoffset 0 → 1(120ms) |
| 240ms | 标题转 `text.tertiary` + 删除线;行透明度 → 0.72 |
| 700ms | 行高度收起 + 透明度 → 0(180ms ease-in)后从列表移除;侧栏计数与项目进度环同步(220ms ease-out) |
| 900ms | 项目完成度到达 100% 时,进度环播放一次高亮脉冲 |

其他:清单展开 220ms ease-out;侧栏折叠 260ms;浮层 pop-in 180ms `scale(.98)→1`;页面切换淡入 160ms。
**必须遵守系统的"减弱动态效果"设置**:开启后所有动效降为 0ms 直接切换。

## 5.1 登录页(新增 v1.1 · **已于 v1.4 废弃**)

> ⛔ **已废弃(v1.4,2026-10-12)**:产品决策「不再需要登录」—— 四端已移除登录页、注册/游客/验证码入口与
> 登录门禁,改为**启动即进主界面 + 后台静默匿名会话**(契约 [03 §7.6.6](03-数据模型与同步协议.md))。
> 本节与 §5.1.1 仅作为历史记录与"将来恢复账号体系"的参考;**当前实现中不得再出现任何登录界面**。

**产品要求(历史)**:启动 App 必须先登录;可选游客登录;数据按用户存云端。契约见 [03 §7.6](03-数据模型与同步协议.md)。

### 布局
- 整屏居中卡片,**宽 400**,高度自适应(约 430~480);卡片 `radius 16` + 12dp 投影;画布 = `canvas` + 一层极淡的品牌渐变光晕(透明度 ≤6%,不喧宾夺主)
- 自上而下:
  1. 品牌区:56 应用图标 + 「Ordo」(`font.display` 24/32,600)+ 副标题「把今天理清楚」(`caption`,textSecondary)
  2. 输入区:邮箱、口令(**带显示/隐藏切换**);浮动标签,聚焦时标签上移 12px 并转 `accent`
  3. 主按钮:高 **44**,`radius 10`,accent 填充,文案「登录」/「注册」(两种模式切换);提交中禁用 + 显示 16dp 转圈
  4. 次要入口:**「以游客身份继续」**(与主按钮同级的次要按钮,`surface` 底 + hairline 描边,**不是灰色小字**)
  5. 底部一行居中文本链接:登录态显示「还没有账号?注册」,注册态显示「已有账号?登录」
- 错误区:主按钮下方固定预留 20 高度;失败时显示 `danger` 文案并**左右抖动**(振幅 6px,320ms,衰减两次)

### 动效与状态
| 时机 | 动效 |
|---|---|
| 进入登录页 | fade + 上移 12px,220ms,`motion.easing.standard` |
| 输入框聚焦 | 边框转 accent,120ms |
| 主按钮按压 | scale → 0.98(90ms) |
| 提交中 | 按钮内转圈;输入框禁用;游客按钮禁用 |
| 登录成功 | 卡片 fade out 160ms → 主界面 fade in 220ms |

### 硬约束
- 必须同时存在**三个入口**:登录 / 注册 / 游客登录;游客登录与正式登录**体验对等**(都能同步,不得做成"功能受限"的灰色入口)
- 触控目标 ≥44;口令框有可读标签;错误不靠颜色单独表达(同时给文字)

### 5.1.1 邮箱验证码登录(v1.3 新增,契约 §7.6.5)

**产品要求**:支持免密登录 —— 邮箱收 6 位验证码,填码即登录;邮箱未注册时服务端自动建号。

#### 入口与切换
- 登录卡片内提供**同级切换**:「口令登录 | 验证码登录」(分段控件或等宽文字切换),**不得**藏进二级页面;
- 两种模式**共用同一卡片骨架**:同一邮箱输入位置、同一主按钮位置;切换时只有"口令行 ↔ 验证码行"互换,卡片高度不跳变(用固定行高 56 兜住);
- 切换**保留已输入的邮箱**;口令与验证码互不清空对方(切回时仍在)。

#### 验证码行

| 元素 | 规范 |
|---|---|
| 验证码输入 | 6 位数字,只接受数字,数字**等宽**(字距 +1.5);**满 6 位自动提交** |
| 获取验证码 | 与输入框**同高(44)的次级按钮**(surface + hairline,与 §5.1 的游客按钮同一形态),位于输入框右侧 |
| 倒计时 | 按响应 `retryAfter`(默认 **60s**)显示「Ns 后重发」并**置灰禁用**;归零恢复「获取验证码」 |
| 主按钮 | 文案「登录」;验证码模式下要求"邮箱格式正确 + 6 位码齐全"才可点,与口令模式一致 |

#### 状态与错误
- 请求中:主按钮 `disabled` + 16dp 转圈(复用 §5.1);**倒计时不因一次失败而丢失**(失败可立即重发,除非服务端给了新的 `retryAfter`);
- 错误沿用 §5.1 错误区(固定预留 20 高 + 抖动 6px/320ms),按服务端 `error.details.reason` 给中文:

| reason | 文案 |
|---|---|
| `code_invalid` | 验证码不正确,请检查后重试 |
| `code_expired` | 验证码已过期,请重新获取 |
| `code_attempts_exceeded` | 尝试次数过多,请重新获取验证码 |
| `code_throttled` | 发送过于频繁,请稍后再试 |

> **倒计时秒数从哪来**:请求成功的 202 响应体顶层 `retryAfter`(秒)用于「Ns 后重发」;
> 而 429 限流错误里的剩余秒数取 **`error.details.retryAfterSec`**(与 §7.4 全局限流同名)。
> 两者位置不同;缺失或非正数时按 **60s** 兜底,超大值做上限夹取。

- **开发模式**:服务端可能返回 `devCode`(仅 `console` 通道 + 显式开关)时,可自动填入验证码框方便联调;**任何生产路径都不得依赖该字段**,UI 上也不解释它;
- 无障碍:验证码输入有可读标签「验证码」;倒计时状态不只靠颜色(文字里带秒数)。

## 5.2 快加号集群(重构:去掉多余元素)

**问题**(用户实测截图):右下角同时存在两个圆形按钮 —— 56dp 的蓝色「+」与 28dp 的白色折叠箭头,视觉上互相叠压,属于**多余元素**。

### 新规范(2026-10-13 按用户指定对齐参照原型;v1.5 修订)
- **只保留一个圆形按钮**:直径 **56**,白色圆头「＋」(与菜单同一枚 20×20 几何,22dp),
  **填充 = `#0A84FF`**(亮蓝;用户给出参照原型截图后指定,**替换原先的 `accent` 靛紫**),
  四周一圈**亮蓝柔光**:用**径向渐变**绘制(厚度令牌 `OrdoSize.fabGlow = 24dp`,量自参照原型
  "按钮边缘最亮、约一个半径处渐隐到透明"),渐变颜色取 `OrdoPalette.fabGlow`。
  ⚠ **不要用 `Modifier.shadow(ambientColor/spotColor)`** —— Compose Desktop(Skia)不渲染彩色阴影,
  实测按钮外 4px 就是背景色(用户当场发现"应该有亮蓝色柔光");
  ⚠ 光晕**不得参与布局**(用 `requiredSize` 溢出按钮边界),否则按钮会被往窗口里推 24dp、离开右下角
- **删除**独立的折叠箭头按钮
- **位置**:右下角,但**必须整体(含光晕)浮在底部状态栏之上** ——
  底边距 = `OrdoSize.statusBar`(34dp)+ `OrdoSize.fabGlow`(24dp)= **58dp**,右边距 `OrdoSpace.xl`。
  ⚠ 少算这一步就会出现"按钮/光晕压住状态栏文案"的叠压(用户实测:亮蓝光晕把右下角「本地」洗成一片蓝);
  已加像素级回归用例(`悬浮按钮与光晕不得压到状态栏`:状态栏那一条里不允许出现偏蓝像素)
- 交互分工:

| 手势 | 行为 |
|---|---|
| **单击** | **展开快捷菜单**(v1.5 起;此前是"直接开输入行",用户按参照原型改回"先出菜单") |
| 长按 400ms | 同样展开菜单(与单击一致,便于触屏长按习惯) |
| 菜单展开中单击 | 收起菜单,按钮转回 0° |

- 新建待办改由**菜单第一项「新建待办」**或快捷键 `Ctrl+N` 触发(输入行行为不变:聚焦 + 列表滚到输入行)
- **动效**(都要有,不能只是"瞬间出现"):
  1. 按钮旋转 0° ↔ 45°(「+」变「×」),`tween` + `FastOutSlowInEasing`;
     *(不用无界 `spring`:在离屏渲染场景里动画永不收敛,会吞掉后续输入事件)*
  2. 菜单淡入 + 从 0.92 缩放(**锚点在右下角**,像从按钮"长出来")+ 自下方上滑
     —— 上滑幅度 **6dp,必须小于面板与按钮间距(8dp)**,否则起始帧面板会盖住按钮、点击被吃掉;
  3. 菜单项错位淡入(每项延迟 40ms、上移 6px)
- ⚠ 手势节点必须用 `rememberUpdatedState` 拿到**最新**回调:`pointerInput(Unit)` 只在首次组合创建,
  直接捕获 `onClick` 会永远读到首次组合时的状态(表现为"菜单展开后再点按钮关不掉")

### 菜单项图标(v1.3 对齐参照原型,四端一致)

菜单仍是 **4 项**(新建待办 / 项目 / 区域 / 标题;**「新建标题」仅在项目视图出现**),前导图标语义统一
(用户指定:照 `things-clone` 参照原型对齐形状;菜单项图标一律用 `textSecondary`,选中/悬停底 `rowSelected`):

| 菜单项 | 图标(20×20 viewBox 的等价形状) | 说明 |
|---|---|---|
| 新建待办 | **＋** | 两条直线 `(4,10)-(16,10)`、`(10,4)-(10,16)`,stroke **2.1**、圆头 |
| 新建项目 | **H** | 两竖 `x=5`/`x=15`(y 4→16)+ 中间一横 `y=10`(x 5→15),stroke **1.7**、圆头 |
| 新建区域 | **圆角方框 + 中心点** | 方框 `rect(3,3,14,14) rx=4`,stroke **1.5**;中心点 `circle(10,10) r=2.6` 实心填充 |
| 新建标题 | **三横线(≡)** | 三条横线 `y=5/10/15`(x 4.5→15.5),stroke **1.7**、圆头;这是 Ordo 自有项,参照原型没有 |

**几何与线宽以本表为准**(四端逐项一致;数值取自参照原型 `i-plus` / `i-heading` / `i-area` 的原始定义)。

> **本表约束的是"菜单项图标"**。FAB 自身的白色「＋」可用平台标准加号(22dp、白色、`accent` 底、
> 展开时旋转 45°),**不要求**与菜单里的 ＋ 逐点同形 —— 两者尺寸与语义不同,强行统一只会让两端为一个
> 不可见的差异返工。反过来说:同一处(菜单内)的四个图标必须四端一致。

**「新建标题」的可用性**(与契约 §2.3 一致):**仅在项目视图**出现 —— heading 必须归属某个 project,
在收件箱/今天/项目列表等视图下这个入口必然失败或静默落到别的项目,因此**隐藏**;其余三项在所有视图可用。
(菜单仍是 4 项,指的是"项目视图下的完整菜单";其它视图显示前三项。)

- 菜单面板:最小宽 **208**、`radius 12`、1px hairline 描边、面板底色 `surface`;条目:高 ≥44、左内边距 9、图标与文字间距 8、字号 13.5(≈`caption` 与 `body` 之间),条目 `radius 7`,悬停/按下底色 `rowSelected`
- 快捷键提示:仅「新建待办」右侧显示 `Ctrl+N`(Windows)/ `⌘N`(macOS),其余项不显示
- 图标一律**矢量绘制**(各端用自有图形能力:Compose `Canvas`/`Path`、ArkUI `Shape`/`Circle`/`Line`、SwiftUI `Path`、或系统符号中形状等价者),不新增位图资源

## 5.3 刷新控件

> ⛔ **已废弃(2026-10-13)**:客户端已**删除云同步**,刷新控件(状态栏同步键 / 下拉刷新 / `Ctrl+R`)
> 随之从三端移除。本节仅作历史记录。

**问题**:原状态栏右侧只是一个可点击的**文字**,点了之后只有文字变化,用户感知不到"刷新了没有"。

### 新规范
- 状态栏右侧改为**图标 + 文字**的刷新控件:28dp 圆形图标按钮(`OrdoIcons.Refresh`)+ 状态文字
- 点击(或 `Ctrl+R` / `⌘R`)后:

| 阶段 | 表现 |
|---|---|
| 同步中 | 图标**连续旋转**(每圈 900ms,linear,持续到结束)+ 文字「同步中…」 |
| 成功 | 图标停转并短暂转 `success` 色(320ms)+ 文字「已同步」,1.4s 后回到常态 |
| 失败 | 图标转 `danger` 色 + 文字「同步失败,点击重试」(常驻,直到重试) |

- 同步进行中按钮禁用(防止重复触发);结束后 1.4s 内保持禁用(防抖)

## 5.4 长按拖拽(统一为独立手势)

**变更**:原先"鼠标直接拖拽"是独立路径,与点击/打开详情容易冲突。统一改为**长按后拖动**这一件事。

| 阶段 | 规范 |
|---|---|
| 按下 | 计时 400ms;**移动 <6px 视为点击**,不进入拖拽(避免抢走"打开详情") |
| 进入拖拽 | 行抬起:scale 1.02 + 12dp 投影 + 背景转 `surface`;给一次轻微触感/音效反馈(平台有则用) |
| 拖拽中 | 插入指示线 2dp `accent`(左端 4dp 圆点);被拖行 alpha 0.55;其余行让位 120ms |
| 松手 | 落库 + 行回落(160ms spring);位置未变则不写库 |
| 取消 | `Esc` / 右键 / 拖出窗口 → 行回到原位,不写库 |

- Windows 行尾的 28dp 拖拽手柄**可以保留**作为"这一行可拖"的可见提示,但**不再是唯一入口**:长按行本身同样可拖;在手柄上按下则**无需长按**直接进入拖拽
- 侧栏项目/标题排序同样遵循本规范

## 8. 无障碍(A11y)基线

- 触控目标 ≥ 44×44(移动)/ 32×32(桌面)。
- 所有交互元素提供可读标签(TalkBack / VoiceOver / 屏幕朗读 / Narrator)。
- 支持系统字体缩放至 200% 不截断(布局允许换行与增高)。
- 不仅靠颜色传达状态:逾期同时有图标与文案,完成同时有勾选图形。
- 深浅色、放大字号、减弱动效三种系统设置必须被遵循。
