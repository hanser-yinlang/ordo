## 2. Android SDK 安装(本轮实际执行)

```powershell
$sdkRoot = "C:\Users\admin\Android\Sdk"
# 1) 命令行工具(136 MB)
Invoke-WebRequest "https://dl.google.com/android/repository/commandlinetools-win-13114758_latest.zip" -OutFile "$sdkRoot\cmdline-tools.zip"
Expand-Archive "$sdkRoot\cmdline-tools.zip" -DestinationPath "$sdkRoot\cmdline-tools\tmp"
Move-Item "$sdkRoot\cmdline-tools\tmp\cmdline-tools" "$sdkRoot\cmdline-tools\latest"

# 2) 许可 + 组件
$env:JAVA_HOME = "<JDK 21>"
$sdkmanager = "$sdkRoot\cmdline-tools\latest\bin\sdkmanager.bat"
(1..40 | ForEach-Object { "y" }) | & $sdkmanager --sdk_root=$sdkRoot --licenses
(1..40 | ForEach-Object { "y" }) | & $sdkmanager --sdk_root=$sdkRoot "platform-tools" "platforms;android-36" "build-tools;36.0.0"

# 3) 告诉 Gradle SDK 在哪(两种方式任选)
#    a) 仓库内 ordo\local.properties: sdk.dir=C:/Users/admin/Android/Sdk
#    b) 环境变量 ANDROID_HOME / ANDROID_SDK_ROOT
```

**已验证的构建命令**
```powershell
$env:JAVA_HOME="C:\Users\admin\Desktop\WeChat\_tools\jdk-21.0.12.1+1"
$env:ANDROID_HOME="C:\Users\admin\Android\Sdk"
cd C:\Users\admin\Desktop\WeChat\ordo
.\gradlew.bat :apps:android:app:assembleDebug      # → BUILD SUCCESSFUL, app-debug.apk ≈ 15.7 MB
.\gradlew.bat :apps:android:app:testDebugUnitTest  # → 4 个测试类 / 60 用例全过
```

> **注意**:Google 的 SDK 源目前最高只提供 **android-36**。因此 AndroidX/Ktor 版本必须选
> "minCompileSdk ≤ 36 且 minAgp ≤ 8.13" 的版本(见 §4 版本矩阵),否则 `checkDebugAarMetadata`
> 会直接失败。

## 3. HarmonyOS 构建(本轮打通)

DevEco Studio 自带全套工具,但 **CLI 构建需要三件事**:SDK 路径、java 在 PATH、工程版本串匹配。

```powershell
$deveco = "C:\Program Files\Huawei\DevEco Studio"
$env:DEVECO_SDK_HOME = "$deveco\sdk"                                    # 必须,否则报 00303217
$env:PATH = "$deveco\jbr\bin;$deveco\tools\node;$deveco\tools\ohpm\bin;$env:PATH"   # 打包阶段需要 java
cd C:\Users\admin\Desktop\WeChat\ordo\apps\harmony
& "$deveco\tools\node\node.exe" "$deveco\tools\hvigor\bin\hvigorw.js" --mode module -p product=default assembleHap --no-daemon
```
**预期输出**:`BUILD SUCCESSFUL`,产物 `entry\build\default\outputs\default\entry-default-unsigned.hap`(≈ 998 KB)。

| 现象 | 原因 | 解法 |
|---|---|---|
| `00303038 Schema validate failed: compatibleSdkVersion must be string` | 版本字段写成了数字 | 改成字符串 |
| `api version parameter is illegal` | 写成 `"26"` 或 `"26.0.0(26)"` | API 26+ 必须写 **`"26.0.0"`**(API 10–25 才写 `"5.0.0(12)"` 形式) |
| `00303217 Invalid value of 'DEVECO_SDK_HOME'` | 未设置该环境变量 | 指向 `<DevEco>\sdk` |
| `spawn java ENOENT` | PATH 里没有 java | 把 `<DevEco>\jbr\bin` 加进 PATH |
| 缺 `hvigor/hvigor-config.json5` | 工程不完整(DevEco 通常会生成) | 从 DevEco 模板复制一份(本仓已补) |

> 签名:当前产出 **unsigned HAP**。装到真机/上架需要在 DevEco 里配置 Huawei 开发者证书
> (`File → Project Structure → Signing Configs`),这一步需要开发者账号,无法在无人值守环境完成。

## 4. 版本矩阵(为什么这么锁)

本机 SDK 上限决定了依赖上限,下面每个约束都用 **AAR 元数据实测**过(`minCompileSdk` / `minAndroidGradlePluginVersion`):

| 组件 | 选定版本 | 为什么不能更高 |
|---|---|---|
| AGP | **8.13.2** | 9.x 需要 Gradle 9,而升级 Gradle 会牵动已验证的核心/桌面端构建 |
| Gradle | **8.14** | 与 AGP 8.13.x、Kotlin 2.4.20 配对 |
| Kotlin | **2.4.20** | 与 Compose MP 1.12.1、KSP 生态现状匹配 |
| compileSdk / targetSdk | **36** | Google 源最高只有 android-36 |
| Compose BOM | **2026.06.01**(compose 1.11.4) | 2026.08/09 的 compose 1.12.x 要 compileSdk 37 |
| androidx.navigation | **2.9.8** | 2.10.x 要 compileSdk 37 / AGP 9.1 |
| androidx.core-ktx | **1.17.0** | 1.19.x 要 compileSdk 37 |
| androidx.activity | **1.13.0** | 兼容线内最新(minCompileSdk 36) |
| androidx.lifecycle / work / datastore | **2.10.0 / 2.11.2 / 1.2.1** | 均在兼容线内 |
| **Ktor** | **3.2.3** | 3.3+ 依赖 OkHttp 5.x,而 OkHttp 5.5 要 compileSdk 37;3.2.3 用 OkHttp 4.12 |
| Compose Multiplatform(桌面) | 1.12.1 | 与 Kotlin 2.4.20 配对,桌面端不受 Android SDK 限制 |

**结论**:只要客户环境能拿到 `android-37` SDK + Gradle 9,就可以整体升到 AGP 9.4.1 / compose 1.12.x / Ktor 3.6;
届时只需改 `gradle/libs.versions.toml` 一处,并重跑 §6 的全量验证。

## 5. 其它两端

### 5.1 Windows 桌面端(本机可跑)
```powershell
$env:JAVA_HOME="C:\Users\admin\Desktop\WeChat\_tools\jdk-21.0.12.1+1"
.\gradlew.bat :apps:windows:test        # 14 用例 + 2 张离屏渲染截图
.\gradlew.bat :apps:windows:run         # 直接运行(需要桌面会话)
```
打 MSI 需要 **WiX 3.x**(jpackage 的 msi 后端);未安装时改用 `packageDistributionForCurrentOS` 生成 app-image。

### 5.2 iOS(必须有 macOS)
```bash
./gradlew :shared:core:assembleXCFramework    # 生成 OrdoCore.xcframework
open apps/ios/Ordo.xcodeproj                  # 详见 apps/ios/README.md
```
`settings.gradle.kts` 里 iOS 目标包在 `HostManager.hostIsMac` 判断内,Windows 上不会创建该任务(正常现象)。

### 5.3 后端(本机可跑)
```bash
cd server && pnpm install && pnpm run build && pnpm test && node scripts/smoke.mjs
```
无 PostgreSQL 时自动降级为内存仓储;接真实库用 `DATABASE_URL` + `pnpm migrate`。

## 7. 本机踩过的坑(务必避开)

1. **`when` 是 Kotlin 硬关键字**:实体属性必须写成 `` `when` ``;用脚本批量改时,**不要碰**反引号标识符(测试函数名)与字符串字面量,否则会把函数名截断(本轮踩过,已用上下文感知脚本修复)。
2. **PowerShell 5.1 的编码陷阱**:`Get-Content -Raw` + `Set-Content -Encoding UTF8` 会把 UTF-8 当 GBK 往返,中文变乱码**且仍然编译通过**。改文件请用编辑器,改完跑 `python tools/check-encoding.py`。`.ps1` 脚本建议**纯 ASCII**(PS 5.1 读无 BOM 的 UTF-8 脚本会解析失败)。
3. **KSP 版本落后于 Kotlin**:本仓 Android 存储层因此不用 Room,改用原生 `SQLiteOpenHelper` + 实体 JSON 表(与服务端 `entities` 表同构)。
4. **验证必须落到"真实构建"**:本轮 Android/HarmonyOS 首次真实编译分别暴露 **23 个 Kotlin 错误**与 **21 个 ArkTS 错误**,此前 60 个单测全绿的"自检"完全没有发现它们。
